# Database Schema Reference

Full reference for every table, view, and extension in the `recon` Postgres database — generated by reading `migrations/0001` through `0026` and resolving every `ALTER TABLE` against its originating `CREATE TABLE`, so what follows is the table's **current** shape, not a chronological log. Each table lists the migration file(s) that created or last changed it, so you can jump to the source of truth if a detail here goes stale.

Conventions used throughout the schema:

- **Money is always an integer in the currency's minor unit** (paise for INR, cents for USD), never a float — columns are named `..._minor`. `currencies.minor_unit` records how many decimal places that implies per currency.
- **`..._home_minor`** is the same amount converted to the owning entity's `home_currency`, stored alongside the original so reports never need a live FX join.
- **`raw JSONB`** columns are a deliberate passthrough: whatever the source file/API sent that didn't map to a named column is kept here, so a new source column never *requires* a migration before it can be captured somewhere.
- **No native Postgres enums.** Every status/type/kind column is plain `TEXT`, validated only in application code (see `docs/data-hub.md` for the rationale — fast-moving categories, no `ALTER TYPE` churn).
- **No ORM, no Alembic.** Every change here is a hand-written, numbered `.sql` file in `migrations/`, applied by `app/db/migrate.py`, tracked in a `schema_migrations` table keyed by filename.

For the data-hub tables (`data_sources`, `field_mappings`, `ingestion_jobs`) and the full ingestion pipeline mechanics, `docs/data-hub.md` has a much deeper treatment (transform engine, worker leasing, API surface, known gaps) — this document keeps those sections concise and defers there for depth.

## 1. Extensions

`0001_extensions.sql` enables `pgcrypto`, which supplies `gen_random_uuid()` — every table's primary key uses it as the default, so every ID in the system is a UUID generated at insert time, never an app-assigned or sequential one (the one exception is `immutable_audit_trail.audit_id`, a `BIGSERIAL` — see [§12](#12-governance--audit)).

## 2. Auth & access

Standard multi-tenant auth: users belong to organizations via role-gated memberships; roles carry permissions; sessions and invitations are separate tables from `users` itself so token lifecycle doesn't bloat the user row.

### `users`

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` PK | Primary key |
| `email` | `varchar(255)` UNIQUE NOT NULL | Login identifier |
| `hashed_password` | `varchar(255)` NOT NULL | Password hash at rest — the plaintext is never stored |
| `full_name` | `varchar(120)` NOT NULL | Display name shown in the UI and resolved into `v_report_matched`/`v_report_runs` |
| `is_active` | `boolean` NOT NULL DEFAULT `true` | Soft-disable flag; not enforced by any FK cascade |
| `is_platform_admin` | `boolean` NOT NULL DEFAULT `false` | Cross-organization admin flag, separate from any per-org role |
| `last_login_at` | `timestamptz` | Updated on successful login; `NULL` for a user who has never signed in |
| `created_at` / `updated_at` | `timestamptz` NOT NULL DEFAULT `now()` | Standard bookkeeping timestamps |

Migrations: `0002`.

### `organizations`

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` PK | Primary key |
| `name` | `varchar(120)` NOT NULL | Display name |
| `slug` | `varchar(60)` UNIQUE NOT NULL | URL-safe identifier |
| `is_active` | `boolean` NOT NULL DEFAULT `true` | Soft-disable flag for the whole tenant |

The tenancy root — every `entity` (legal company/site) belongs to exactly one organization. Migrations: `0003`.

| `name` | `text` NOT NULL | Full currency name, e.g. "Indian Rupee" |
| `minor_unit` | `smallint` NOT NULL DEFAULT `2` | Decimal places implied by every `..._minor` column referencing this currency |

Migrations: `0008`.

### `entities`

| Column | Type | Notes |
|---|---|---|
| `entity_id` | `uuid` PK | Primary key |
| `organization_id` | `uuid` FK → `organizations`, ON DELETE CASCADE | Owning organization — every entity belongs to exactly one |
| `company_code` | `text` NOT NULL | Short internal code for the legal entity/site, unique within the organization |
| `name` | `text` NOT NULL | Display name of the entity |
| `site_code` | `text` | Optional sub-location code when an entity spans multiple sites |
| `home_currency` | `char(3)` NOT NULL DEFAULT `'INR'`, FK → `currencies` | Currency entity-level `..._home_minor` columns convert into |

| `created_at` / `updated_at` | `timestamptz` NOT NULL DEFAULT `now()` | Standard bookkeeping timestamps |

UNIQUE `(organization_id, company_code)`. This is the legal-entity/subsidiary row nearly everything else (`gl_accounts`, `customers`, `invoices`, `bank_statements`, `reconciliation_definitions`, ...) hangs off via `entity_id`. Migrations: `0008`.

UNIQUE `(from_ccy, to_ccy, rate_date, rate_type)`. Migrations: `0008`.

### `gl_accounts`

| Column | Type | Notes |
|---|---|---|
| `gl_account_id` | `uuid` PK | Primary key |

## 4. Customers & AR master data

### `customers`

| Column | Type | Notes |
|---|---|---|
| `customer_id` | `uuid` PK | Primary key |
| `entity_id` | `uuid` FK → `entities` | Owning entity |
| `customer_code` | `text` NOT NULL | Case-insensitively unique per entity — see `uniq_customers_code_ci` below |

| `pan` / `gstin` | `text` | Indian tax identifiers, used by customer-identification matching rules |
| `vpa_handle` | `text` | UPI virtual payment address |
| `payment_terms` | `text` | Free-text payment terms, e.g. "Net 30" — descriptive only |
| `credit_limit_minor` | `bigint` | Credit limit in minor units of the entity's home currency; not enforced by any constraint |
| `city` / `state` | `text` | Address fields, used for reporting/segmentation |
| `created_at` / `updated_at` | `timestamptz` NOT NULL DEFAULT `now()` | Standard bookkeeping timestamps |
| `raw` | `jsonb` | Passthrough of unmapped source columns (`0019`) |
| `source_job_id` | `uuid` FK → `ingestion_jobs` | Which ingestion job created this row (`0022`) |
| `valid` | `boolean` NOT NULL DEFAULT `true` | (`0022`) |
| `issues` | `text[]` | Validation problems noted at ingest time, row still inserted (`0022`) |

Indexes: `idx_customers_gstin`; `idx_customers_name` (GIN full-text on `company_name`); `uniq_customers_code_ci` — a case-insensitive unique index on `(entity_id, upper(customer_code))` added in `0025` as a backstop so a code path that forgets to normalize case still can't create a duplicate customer. Migrations: `0009`, `0019`, `0022`, `0025`.

### `ingestion_jobs` — one row per upload, and the worker queue itself

| Column | Type | Notes |
|---|---|---|
| `job_id` | `uuid` PK | Primary key |
| `source_id` | `uuid` FK → `data_sources` | Which data source this job ingested for |
| `file_name` / `format` | `text` | `format`: only `CSV` is actually parsed today — `XLSX`/`MT940`/`OFX` are accepted as valid values but fail every job that uses them |
| `trigger_type` | `text` NOT NULL DEFAULT `'MANUAL'` | Always `'MANUAL'` in the current code — the column exists for a future scheduled/webhook trigger path |
| `row_count` / `error_count` | `int` NOT NULL DEFAULT `0` | Rows read and rows rejected for this job; set when the job finishes |
| `status` | `text` NOT NULL DEFAULT `'PENDING'` (was `'RUNNING'` before `0020`) | Lifecycle e.g. `PENDING` → `RUNNING` → `SUCCEEDED`/`FAILED`; see `0020`'s lease/retry columns below |
| `started_by` | `uuid` FK → `users` | Always `NULL` today — auth isn't wired into the ingestion path yet |
| `started_at` | `timestamptz` NOT NULL DEFAULT `now()` | When the job was created/enqueued, not when a worker actually claimed it |
| `locked_by` / `locked_at` / `lease_expires_at` | `text` / `timestamptz` / `timestamptz` | Lease-based claiming (`0020`) — a worker does `SELECT ... FOR UPDATE SKIP LOCKED`, and a dead worker's job self-heals once the lease expires |
| `attempt_count` / `max_attempts` / `next_attempt_at` / `last_error` | | Exponential-backoff retry state (`0020`); dead-letters to `FAILED` past `max_attempts` |
| `file_uri` | `text` | (`0020`) |
| `job_type` | `text` NOT NULL DEFAULT `'INGEST'` | (`0021`) — historically `INGEST` vs `PROMOTE`, but `PROMOTE`/staging was removed in `0022` (see [§14](#14-removed-tables)); `INGEST` is the only live value today |
| `parent_job_id` | `uuid` FK → `ingestion_jobs` | (`0021`) |
| `stream` / `mapping_version` | `text` / `int` | (`0021`) |
| `failed_rows` | `jsonb` | Rows that couldn't satisfy a canonical table's NOT NULL columns — diagnostic only, fixing means correcting the source and re-uploading, not an in-app edit (`0022`) |
| `content_hash` | `text` | Per-job file content hash, rejects re-uploading the identical file (`0025`) |
| `unmapped_columns` | `text[]` | Raw columns that matched no synonym in the active stream mapping and that the (stubbed) AI-suggestion step couldn't resolve either (`0026`) |

Index: `idx_ingestion_jobs_claimable` on `(status, next_attempt_at)`; `idx_ingestion_jobs_content_hash` on `(source_id, content_hash)`. Migrations: `0011`, `0020`, `0021`, `0022`, `0025`, `0026`.

### `field_mappings` — how to translate a stream's raw columns

| Column | Type | Notes |
|---|---|---|
| `mapping_id` | `uuid` PK | Primary key |
| `stream` | `text` NOT NULL | Scoping key as of `0026` — **not** `source_id` (that column was dropped); one mapping set is shared by every data source/entity/org ingesting that stream |
| `version` | `int` NOT NULL DEFAULT `1` | Mapping-set version for the stream; lets a new mapping be staged without touching rows already ingested under the old one |
| `source_field` | `text` NOT NULL | Raw column name as it appears in the source file; multiple rows may target the same `canonical_field` as synonyms |
| `canonical_field` | `text` NOT NULL | Target column on the stream's real table |
| `transform` | `text` NOT NULL DEFAULT `'NONE'` | One of 9 transforms applied to the raw value (`NONE`, `CONST`, `TO_MINOR_UNITS`, `PARSE_DATE`, `REGEX`, ...) — see `docs/data-hub.md` §4 |
| `transform_param` | `text` | Meaning depends on `transform` — e.g. the constant for `CONST`, the multiplier/negate flag for `TO_MINOR_UNITS`, the date formats for `PARSE_DATE`, the capture pattern for `REGEX` |
| `is_active` | `boolean` NOT NULL DEFAULT `true` | Lets a synonym row be retired without deleting history |

Migrations: `0011` (create, originally `source_id`-scoped), `0026` (add `stream`, backfill from `data_sources.stream`, `NOT NULL`, drop `source_id`).

## 13. Reporting views

Both are plain `CREATE VIEW` (not materialized) — always live, no refresh step.

### `v_report_matched`

Joins `invoice_allocations` → `match_groups` → `reconciliation_runs` → `invoices` → `customers`, left-joins `bank_statements` and the matching `users` row, filtered to `reconciliation_runs.status IN ('APPROVED', 'CLOSED')`. One row per allocation line in a finalized run — the "what matched to what, and who matched it" report.

### `v_report_runs`

One row per `reconciliation_runs` row, with `prepared_by`/`reviewed_by` resolved to `full_name` via correlated subqueries against `users`. The run-history/summary report.

Migrations: `0018`.

## 14. Removed tables

### `staging_records` — created `0011`, dropped `0022`

Originally the landing zone for every ingested row before a separate `PROMOTE` job copied reviewed rows into canonical tables (`stream`, `txn_date`, `reference`, `counterparty`, `amount_minor`, `amount_home_minor`, `currency`, `dr_cr`, `raw jsonb`, `valid`, `issues`). Replaced by direct-to-canonical ingestion: a parsed row is now written straight into `bank_statements`/`invoices`/`customers`, each of which gained its own `valid`/`issues`/`raw`/`source_job_id` columns to take over the job this table existed for. Rationale (from `0022`'s migration comment): the generic shape could never represent any one stream's real columns anyway (no `document_number`, `due_date`, `tds_rate_pct`, ...), so "promotion" would have had to re-derive most fields regardless. See `docs/data-hub.md` §1 for the full writeup.
